Building a mode plugin

This guide walks through writing a mode that docks above the shell the same way commander, chat and preferences do. The wire format, host calls and crash behaviour are specified in Mode plugin protocol; Plugins covers manifests, installs and permissions. Read this page to get a first plugin running, then keep the protocol open as the reference.

Mouser 1.4.0 freezes api 1. The bundled commander, chat and preferences plugins run on it, and so can yours.

What you are building

A mode is its own executable. Mouser starts it the first time the mode is used and keeps it running. stdin/stdout carry framed MessagePack (or JSON); stderr goes to Mouser's plugin log. The plugin runs as you, with your rights — it is not a sandbox. Every request and effect is checked against the permissions you granted.

Two paths exist:

path when to use transport
Mode protocol (mouser-mode-api) a real dock with views, images, host calls, context menus transport = "mode"
Command mode (one-shot JSON) a tiny demo or shell script that returns title/lines transport = "command"

The rest of this guide is the mode-protocol path. The tree also ships examples/plugins/hello-mode for the one-shot command path.

Minimal plugin.toml

name = "hello"
version = "0.1.0"
permissions = ["files.read"]

[[provides]]
kind = "mode"

[run]
transport = "mode"
command = ["./hello-mode"]   # path relative to the plugin directory

[mode]
hotkey = "h"
keys = [{ id = "refresh", key = "r", describe = "refresh" }]

Install and allow it:

mouser plugin install ./hello
mouser plugin permissions hello run=allow files.read=allow

It joins the mode switcher (esc :h). Mouser starts it the first time the mode is drawn. A bound key or a click arrives as ui.action, typing as input.text while a field has focus, and the shell's folder as shell.cwd_changed (with files.read).

Writing it in Rust

Depend on the public crate and implement Mode, then call serve from main. Only hello is required; the other methods have defaults.

# Cargo.toml
[dependencies]
mouser-mode-api = "0.2"
serde_json = "1"

use mouser_mode_api::events::{Event, Listener};
use mouser_mode_api::protocol::{ApiRange, Handled, Hello, Provide};
use mouser_mode_api::{Host, Mode, serve};
use serde_json::json;

struct Hello;

impl Mode for Hello {
    fn hello(&self) -> Hello {
        Hello {
            api: ApiRange::CURRENT,
            name: "hello".into(),
            version: env!("CARGO_PKG_VERSION").into(),
            provides: vec![Provide::Mode {
                hotkey: 'h',
                bindings: vec![],
                activate_on: vec![],
            }],
            listeners: ["ui.action", "shell.cwd_changed", "mode.activated"]
                .iter()
                .map(|e| Listener::on(e))
                .collect(),
            emits: vec![],
            wants_mcp: false,
            shm: false,
        }
    }

    fn event(&mut self, e: &Event, host: &Host) -> Handled {
        match e.name.as_str() {
            "mode.activated" | "shell.cwd_changed" | "ui.action" => {
                let cwd = e.payload.get("cwd").and_then(|v| v.as_str()).unwrap_or("?");
                let _ = host.view(
                    Some(format!("hello — {cwd}")),
                    Some(vec![format!("event: {}", e.name), "press r to refresh".into()]),
                    vec![],
                    true,
                );
            }
            _ => {}
        }
        Handled::Handled
    }
}

fn main() {
    let _ = serve(Hello);
}

crates/mouser-mode-api/src/bin/echo.rs is a complete small example used by the crate's tests: it answers frame.tick with a 1080p frame, echoes custom events and restores state after a crash.

Build the binary, put it next to plugin.toml as ./hello-mode (or change command), then install as above.

JSON instead of MessagePack

Set MOUSER_MODE_WIRE=json to speak JSON frames. Useful while debugging from another language; MessagePack stays the default.

What arrives and what you send

In (events): mode.activated / mode.deactivated, ui.action (a bound key or a click), input.text / input.key / input.escape while you asked for the keyboard, shell.cwd_changed, shell.remote_* with remote.read, menu.open for context menus, view.resized (including dock size), frame.tick when you draw video, agent.state when you run an agent session.

Out: View (dock / panel / images), Effect (type into the shell, cd, open a URL, a status line), Request (host calls), Emit, Menu, StateSave, Wants (what the keyboard should give you right now).

The full tables live in Mode plugin protocol §§Events, Messages from the plugin, Host calls, Images, Host services.

Host calls you will use first

Declare every permission in plugin.toml and grant it before the call works:

call permission use
prefs.schema / prefs.get none read preferences (secrets only say they are set)
prefs.set / prefs.reset prefs.write write non-secret prefs
prefs.secret_prompt prefs.write Mouser's popup saves a key to the keychain; you never see it
Fs read / list / stat files.read local files, never the secrets deny-list
fetch net.fetch one HTTP(S) request made by Mouser
remote.* remote.read files on the shell's ssh host
agent.* agent.use chat with the user's models and keys inside Mouser
Approve / permissions.request none Mouser's own popup

Mouser's popups name your plugin, take every key while open, and ignore clicks for the first 400 ms so nothing in the tab can answer them for you.

Context menus and MCP

Answer menu.open with the actions that apply to the item under the pointer (or the selection, when the menu key . was used). Build the list from the same registry as your key bindings. Mouser draws the menu and turns a pick into ui.action.

The same answer also feeds Mouser's MCP tools mode_actions / mode_action, so anything on your menu is scriptable once you answer menu.open. Keep destructive work behind your own confirmation; Mouser asks the user once (modes.control) as well. See the protocol §Over MCP and MCP §Mode actions.

Crashes and restarts

Mouser restarts a crashed mode plugin with backoff (1 s, 2 s, 4 s) up to plugins.max_restarts (default 3), then shows a Restart action. Whatever you last sent with StateSave comes back in Welcome.restore. The terminal is never taken down by a plugin crash.

Checklist before you ship

  1. plugin.toml name matches Hello.name, and command finds the binary.
  2. Every host call's permission is listed and granted.
  3. Destructive menu entries confirm in the plugin and survive an MCP client picking them.
  4. Wants is cleared when a field closes, so keys return to the shell.
  5. You tested a crash: kill the process and confirm it restores cleanly.
